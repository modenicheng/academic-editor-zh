# 抽象黑话与英文直译污染

## 判断法

遇到抽象词，不先问“这个词能不能用”，先问：

1. 它具体指什么？
2. 能否写成明确条件、动作、指标、对象或结果？
3. 删除后是否损失学科含义？
4. 该词在本领域是否已有稳定、可检索的术语义？

若 1 无法回答、2 可以做到、3 不损失、4 否，则改写。

## 高频警报词与改写

### 口径

可保留：统计口径、会计口径等已有稳定含义。

不佳：为保证公平比较，本文统一实验口径。

改：为保证公平比较，各方法使用相同数据集、指标、训练预算和测试流程。

不佳：两组结果口径不一致。

改：两组结果采用不同指标/样本范围/统计方法。[按实际情况写明差异]

### 门禁

可保留：实体门禁系统、访问控制领域明确术语。

不佳：系统设置质量门禁，阻止不合格数据进入正式链路。

改：系统仅允许通过质量校验的数据进入发布流程。

不佳：该检查作为发布门禁。

改：发布前必须通过该检查。

### 闭环

不佳：形成从检索到发布的完整闭环。

改：系统依次完成检索、解析、验证和发布，并记录各阶段结果。

“闭环控制”若指控制理论术语则保留。

### 链路

不佳：数据沿验证链路进入下游模块。

改：系统先验证数据，再交给下游模块处理。

网络通信、射频等领域“链路”有明确术语义时保留。

### 基座

不佳：该模块构成系统的数据能力基座。

改：该模块提供统一的数据读取、校验和存储接口。

### 能力

不佳：系统具备多源检索能力与自动验证能力。

改：系统可检索多个数据源，并自动验证结果。

### 对齐

不佳：实验设计与真实任务场景保持对齐。

改：实验采用与真实任务相同的输入约束和评价指标。

“序列对齐”“表示对齐”等已有技术术语可保留。

### 颗粒度

不佳：我们以更细颗粒度记录证据。

改：系统为每条记录保存来源、定位信息和验证结果。

### 兜底

不佳：人工审核作为最终兜底机制。

改：自动校验无法判定时转交人工审核。

### 沉淀

不佳：系统将运行经验沉淀为可复用规则。

改：系统把已验证规则保存到配置中，供后续任务复用。

### 赋能

不佳：该框架赋能领域研究人员高效分析数据。

改：该框架减少数据准备步骤，使研究人员可直接分析经过验证的数据。

### 抓手

论文正文通常不用。

不佳：以自动验证作为提升数据质量的核心抓手。

改：本文通过自动验证提高数据质量。

### 机制 / 框架 / 路径 / 维度 / 范式 / 生态

这些词本身并非错误，但极易充当“想不清楚时的占位符”。

不佳：构建多维度协同机制，探索新的技术路径。

改：说明参与对象、协同方式、具体方法与评价标准；若无法展开，删除该句。

## 几乎不应直接进入中文学术正文的组合

以下表达常见于 AI、管理黑话或英文概念逐词映射。除非作者能给出严格术语定义，否则重写：

- “构建能力基座”
- “形成验证闭环”
- “打通数据链路”
- “设置质量门禁”
- “统一实验口径”
- “沉淀方法论资产”
- “实现能力复用”
- “完成认知对齐”
- “以……为抓手”
- “赋能下游任务”
- “提升流程韧性”〔若不是 resilience 的明确研究对象〕
- “构筑技术护城河”
- “形成端到端能力”〔直接描述端点和步骤〕
- “建立统一事实源”〔若实际指 single source of truth，写清哪个数据源以及如何保证一致〕
- “在……维度下进行能力刻画”
- “实现从 X 到 Y 的跃迁”〔除非有明确量化证据〕

## 英文原词处理

- 有稳定中文译名：首次写“中文译名（英文原文）”，后续只用中文。
- 中文译名不稳定或可能歧义：首次保留英文，之后选定一种写法。
- 代码标识符、字段名、模型配置名、错误码不放入正文句子；论证确需时放表格、脚注或附录。
- 不因英文论文常用 `pipeline / gate / loop / alignment / capability / framework` 就在中文里机械对应为“链路 / 门禁 / 闭环 / 对齐 / 能力 / 框架”。先翻译语义，再选中文句法。
